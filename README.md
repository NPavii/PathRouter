# Караван (PathRouter)

WinUI 3 приложение для создания «цифровых путей» — маршрутов перемещения файлов
(источник → название пути → назначения) с двумя видами графа: слоистым и силовым
(«как в Obsidian»). Название и иконка-верблюд — отсылка к торговым караванам старого мира.

## Установка (standalone)

Готовая сборка не требует установленного .NET — runtime входит в поставку.

1. Собрать (или взять из релиза):

   ```
   powershell -ExecutionPolicy Bypass -File deploy.ps1
   ```

2. Скопировать папку `publish\` (~215 МБ) в любое место — `C:\Program Files\Караван`,
   съёмный диск, сетевую папку. Запуск — `Караван.exe`.

3. Данные (маршруты, манифесты, настройки) живут в `%LocalAppData%\PathRouter\` и не
   привязаны к месту установки. Перенос на другую машину: экспорт БД («Экспорт БД»)
   или копия файла `routes.db`.

Системные требования: Windows 10 19041+ / Windows 11, x64.

## Сценарий работы

1. Перетащите файлы/папку в зону слева (или «Указать исходную папку…») — приложение
   запоминает **начало пути**.
2. Введите название, выберите папку назначения, «Положить» — файлы **копируются** в
   назначение (источник остаётся и дальше отслеживается), на графе появляется
   `источник → название → назначение`.
3. Выберите маршрут → «В новую папку…» (или перетащите папку из проводника прямо на
   маршрут) — ветвей может быть сколько угодно.
4. Фоновые watcher'ы на источниках замечают изменения за ~5 секунд (страховочный полный
   проход — каждые 60 с): над ветвью оранжевый бейдж **↻** — в источнике новее;
   красный **≠** — в самой папке назначения изменились «наши» файлы.
5. Клик по бейджу (или «Обновить все») синхронизирует ветвь с источником. Удаляются
   только файлы, которые маршрут сам положил и которых больше нет в источнике;
   чужие файлы в общей папке не трогаются. Перед удаляющей синхронизацией — подтверждение.

## Ключевые механики

- **Пути (группы).** Выделите несколько маршрутов галочками → ПКМ → «Объединить в путь…»:
  общий контур на графе, заголовок в списке, переименование (✎), сворачивание
  до плашки «▸ Имя — N маршрутов».
- **Консервация.** ПКМ по ветви на графе → «Законсервировать»: проверка и синхронизация
  этой ветви отключены (пунктирный контур), остальные работают. «Вскрыть» — вернуть.
- **Конфликты.** Если файл правился в источнике и в получателе к разному содержимому —
  «⚠ конфликт»; при синхронизации версия получателя сохраняется как
  `имя.конфликт-ГГГГММДД-ЧЧММСС.ext`.
- **Цепочки (транзит).** Если Б — назначение одного маршрута и источник другого
  (А→Б, Б→В), файлы текут транзитом. На слоистом графе блоки выстраиваются
  последовательно и связаны пунктирными дугами; в силовом виде общая папка — одна
  точка с лучами.
- **Контентный хэш.** Изменения детектятся по содержимому (размер + первые/последние
  64 КБ), а не по дате: перекопированный через архив файл не считается «изменённым».
- **Поиск файла.** «Найти файл по всем путям…» — все известные копии по всем маршрутам;
  клик — показать маршрут, двойной клик — открыть папку с копией.
- **Заметки к ветвям.** ПКМ по узлу назначения → «Заметка…»: многострочный текст,
  на узле появляется ✎ (правый нижний угол); наведение — всплывающий просмотр, клик —
  снова редактировать. В диалоге есть «Удалить заметку».
- **Импорт/экспорт БД** (кнопки под фильтрами): SQLite-файл целиком, с валидацией.
- **Тёмная тема** — кнопка с иконкой луны в тулбаре, выбор запоминается.

## Граф

- **Слоистый вид:** общие узлы источников, контуры путей, бейджи состояний,
  свободное перетаскивание блоков по полю (X и Y, позиции сохраняются между запусками;
  пунктирные дуги цепочек пересчитываются на лету), колесо — масштаб от курсора,
  двойной клик по узлу — открыть папку.
- **Силовой вид («как в Obsidian»):** точки-папки, линии-ветви со стрелками, физика
  (отталкивание/пружины/гравитация — ползунки в тулбаре, «Перемешать заново»),
  наведение затемняет не-соседей, перетаскивание точек прибивает их,
  позиции сохраняются.

## Структура решения

```
src/PathRouter.Core        — модели, SQLite-хранилище, сканирование/снапшоты/диффы, файловые операции
src/PathRouter.App         — WinUI 3 (unpackaged): MainWindow (partial-классы), GraphCanvas, ForceGraphView
src/PathRouter.SmokeTest   — консольный прогон всего сценария (70+ проверок)
src/PathRouter.SeedDemo    — засев демо-данных
deploy.ps1                 — сборка standalone-релиза в publish\
```

## Сборка из исходников

ВАЖНО: XAML-компилятор Windows App SDK ломает XBF при проектной сборке — только через solution:

```
dotnet restore PathRouter.sln
dotnet build PathRouter.sln -c Release
dotnet run --project src/PathRouter.SmokeTest   # smoke-тест логики
```

Standalone-релиз — `deploy.ps1` (три шага: solution build → self-contained publish →
подмена XBF/.pri; детали в комментариях скрипта). Single-file публикация WinApp SDK
не поддерживает — только папка.

## Хранение данных

- `routes`: id, название, путь источника, флаги архивный/скрытый/свёрнут, путь-группа.
- `destinations`: ветви (папка, порядок, время синхронизации, консервация).
- `manifest`: снапшот источника на момент синхронизации (путь, размер, mtime, контентный хэш).
- `route_groups`, `layout`, `force_layout`: состояние путей и ручная раскладка обоих видов.

Миграции схемы выполняются автоматически при запуске (`PRAGMA table_info` + `ALTER TABLE`).
Все методы репозитория потокобезопасны — UI и фоновые watcher'ы ходят в БД параллельно.

## CI

GitHub Actions (`.github/workflows/ci.yml`): restore → build через solution → smoke-тест
на `windows-latest`. Логика Core (`net8.0`) кроссплатформенна, UI — только Windows.
