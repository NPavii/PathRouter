# Караван (PathRouter)

WinUI 3 приложение для создания «цифровых путей» — маршрутов перемещения файлов
(источник → название пути → назначения) с интерактивным графом.
Название и иконка-верблюд — отсылка к торговым караванам старого мира.

## Запуск

Готовая сборка: `dist/Караван.exe` (требуется .NET 8 Desktop Runtime — на машине разработки установлен).

Данные хранятся в `%LocalAppData%\PathRouter\routes.db` (SQLite). Демо-маршруты уже засеяны.

## Сценарий (по ТЗ)

1. Перетащите файлы/папку в зону слева (или нажмите **«Указать исходную папку…»**) → приложение запоминает **начало пути**.
2. Введите название пути, выберите папку назначения, нажмите **«Положить»** — файлы **копируются** в назначение
   (исходники остаются на месте — источник дальше отслеживается на изменения), создаётся маршрут,
   на графе появляется `источник → название → назначение`.
3. Если исходная папка маршрута пропала, маршрут подсвечивается **красным** («источник не найден»).
3. Выберите маршрут → **«Положить в новую папку»** — файлы копируются из того же источника в новую папку,
   в графе добавляется вторая ветвь.
4. **«Проверить обновления»** — двусторонняя проверка: изменился источник — над ветвью оранжевый бейдж **«↻»**;
   изменились сами «свои» файлы в папке назначения — красный бейдж **«≠»**.
5. Клик по бейджу (или **«Обновить все»**) — назначение приводится к состоянию источника: новые/изменённые
   файлы копируются, из назначения удаляются только файлы, **которые этот маршрут сам туда положил и которых
   больше нет в источнике** (перед удаляющей синхронизацией — подтверждение с количеством файлов).
   **Чужие файлы в папке назначения не трогаются**: несколько маршрутов могут вести в одну папку,
   каждый отвечает только за свои файлы. Дубли внутри одного маршрута запрещены:
   одна папка — одна ветвь, назначение не может совпадать с источником.
6. Двойной клик по узлу источника/назначения — открыть папку в проводнике.

## Автонаблюдение и поиск

- **Фоновые watcher'ы** висят на всех исходных папках: изменение источника подсвечивается бейджем
  за ~5 секунд без нажатия кнопок. Раз в 60 с идёт страховочный полный проход —
  он ловит правки внутри папок-назначений (бейдж «≠»).
- **Поиск файла** (поле «Найти файл по всем путям…») — обратный просмотр: показывает все известные
  копии файла по всем маршрутам и ветвям (из манифестов синхронизации). Клик по результату выбирает
  маршрут, двойной клик открывает папку с копией.

## Пути (группы) и сворачивание

- Выделите несколько маршрутов (**Ctrl/Shift + клик**) → ПКМ → **«Объединить выбранные в путь…»**:
  маршруты получают общий путь, на графе их объединяет общий контур с названием пути,
  в списке слева они живут под заголовком пути.
- **Свернуть маршрут** (ПКМ по маршруту или шеврон ▾ на графе) — схлопывается до одного узла-названия.
- **Свернуть путь** (ПКМ, кнопка в заголовке группы или клик по заголовку контура на графе) —
  весь путь схлопывается до одной плашки «▸ Имя — N маршрутов».
- Пустой путь расформировывается автоматически; «✕» в заголовке группы — разгруппировать.

## Консервация ветви

ПКМ по узлу назначения на графе → **«Законсервировать»**: проверка целостности и синхронизация
этой ветви отключаются (пунктирный контур, ❆). Если к одной папке прикреплено 10 маршрутов,
каждый можно законсервировать независимо — остальные продолжают работать.
**«Вскрыть»** возобновляет проверку: ветвь увидит все изменения, накопившиеся за время консервации.

## Импорт / экспорт базы

Кнопки **«Экспорт БД» / «Импорт БД…»** (под фильтрами списка) — база SQLite целиком.
Экспорт: копия `%LocalAppData%\PathRouter\routes.db` в выбранный файл.
Импорт: выбранный файл проверяется (таблицы routes/destinations/manifest), затем заменяет
текущую базу; файлы на диске не затрагиваются.

## Граф

Маршруты с **одной и той же исходной папкой** сходятся в общий узел-источник:
один узел слева, из него веером — названия маршрутов, из каждого — ветви назначений.
Колесо мыши — масштаб (от курсора), перетаскивание фона — панорама,
клик по узлу — выбор, кнопка «Сбросить вид» — авто-масштаб.

## Структура

```
src/PathRouter.Core        — модели, SQLite-хранилище, сканирование/снапшоты/диффы, файловые операции
src/PathRouter.App         — WinUI 3 (unpackaged), главное окно, Drag&Drop, GraphCanvas (Win2D)
src/PathRouter.SmokeTest   — консольный прогон всего сценария (все проверки зелёные)
src/PathRouter.SeedDemo    — засев демо-данных
```

## Сборка

ВАЖНО: из-за особенности XAML-компилятора Windows App SDK сборка должна идти через solution-файл
(проектная сборка `dotnet build src/PathRouter.App` молча ломает XBF → 0xc000027b при запуске):

```
dotnet restore PathRouter.sln
dotnet build PathRouter.sln -c Release        # вывод: src/PathRouter.App/bin/x64/Release/...
```

Smoke-тест логики: `dotnet run --project src/PathRouter.SmokeTest`

## Готовая сборка (dist)

`dotnet publish` на уровне проекта **не использовать** — та же ловушка с XBF, краш
`XamlParseException` при запуске. Рабочий рецепт — собрать solution (см. выше) и скопировать
вывод, как сделан существующий `dist/`:

```
dotnet build PathRouter.sln -c Release
robocopy src\PathRouter.App\bin\x64\Release\net8.0-windows10.0.19041.0 dist /MIR
```

## CI

GitHub Actions (`.github/workflows/ci.yml`): restore + build через solution, прогон smoke-теста
на `windows-latest`. Логика Core (`net8.0`) кроссплатформенна, UI — только Windows.

## Хранение путей

- `routes`: id, название, путь источника, флаги архивный/скрытый.
- `destinations`: ветви маршрута (папка назначения, порядок, время последней синхронизации).
- `manifest`: снапшот источника на момент синхронизации (относительный путь, размер, mtime, FNV-1a хэш).

Изменения детектятся сравнением текущего сканирования источника с манифестом каждой ветви
(+n новых, ~n изменённых, -n удалённых). Проверено на 500+ маршрутах (~0,8 с на вставку).

## Инженерные заметки

- Все методы `RouteRepository` потокобезопасны (синхронизация на уровне метода) —
  фоновые watcher'ы и UI ходят в БД параллельно, UI не держит внешних блокировок.
- Запись в БД и копирование файлов разведены: провал копирования откатывает
  создание маршрута/ветви (не остаётся «битых» записей).
- `DetermineSourcePath` отклоняет элементы с разных дисков явным `ArgumentException`
  (раньше молча возвращал текущий каталог процесса).
